# What was actually verified

Verification date: 5 October 2026. These records describe this delivered prototype, not claimed production readiness.

## Automated checks

The tests cover position formats; numeric/string labels; missing-label rejection; baseline-only label assumptions; nested ZIP reading; Windows path splits; JSON/JSONL containers; cross-split exact-file rejection; no ground-truth feature leakage; no label-dependent model inputs; causal history/target separation; duplicate preservation; gap resets; time-order validation; optional map geometry; model shapes/backpropagation; weighted FedAvg; calibration serialization; uncertainty policies; undefined metrics; and saved-model streaming/offline parity.

Run `python -m pytest -q` to repeat them. The release includes `TEST_RESULTS.txt` with the executed test result.

## Synthetic end-to-end run

Configuration: `configs/demo.yaml`; seeds 7, 19, 43; centralized and federated training; both classical baselines; seven neural stream subsets; strict and alert policies. The fixture has normal, constant-position-offset, delayed, duplicated/flooding and reversed-heading messages.

Prepared windows: 3,300 train, 1,650 selection, 1,375 score-reference, 275 threshold-calibration and 19,860 test. These are generated toy data, not real VeReMi traffic. Reloading the saved federated seed-7 checkpoint reproduced decisions exactly and the maximum score difference was 0.0 in the checked environment.

Measured outputs are retained under `examples/verified_demo/`. Some baselines and single streams outperform the full fused model on this fixture. The reports are not filtered to favour the proposal.

MD5 is recorded here as a release-integrity comparison, not a security guarantee. Per-JSON SHA-256 hashes are also retained in the ingestion audit. No raw external dataset is redistributed in this ZIP.

The importer read nested official archives and parsed 144,196 records from 1,586 used JSON files. It applied the explicitly declared clean-baseline assumption to 99,937 baseline records that omitted attacker labels. Attack Train/Validation were excluded by the experiment protocol; attack Test labels were retained.

Prepared windows: 18,401 train; 4,542 model-selection; 3,016 score-reference; 2,525 threshold-calibration; 42,664 test. Those test windows contain 4,116 attack-labelled examples and 38,548 benign examples across baseline Test and the constant-offset Test archive. Baseline traffic can be repeated across those test variants, so pooled numbers are only descriptive.

Configuration: `configs/demo.yaml`, seed 7, three active receiver-hash virtual clients, four centralized epochs and three federated rounds with one local epoch each. This is intentionally a **short compatibility pilot with unequal training budgets**, not the final 5-client research experiment. Road-map features were unavailable; only neighbour context was active.

## Pilot findings that must not be hidden

The full three-stream method performed poorly on this constant-offset pilot. Its pooled strict-policy F1 was approximately 0.0325 centrally and 0.0598 under FedAvg. ROC-AUC was approximately 0.4543 and 0.4879, respectively. This does **not** establish effective constant-offset detection or superiority over baselines. See the exact CSVs and per-scenario/attack breakdowns instead of rounding these into an improvement claim.

Only about 48% of raw test messages had sufficient history to be scored, with attack-labelled coverage about 47.3%. This is a significant limitation of history-based evaluation on short pseudonym tracks; report coverage alongside detection metrics.

The three neural models together contain 11,323 trainable parameters. The checked float32 checkpoint was 53,953 bytes, with 45,292 parameter payload bytes. On this environment the pilot federated model's median batch-1 inference-plus-fusion time was about 0.662 ms and p95 about 1.064 ms across 100 samples. This excludes feature construction, parsing, networking, warm-up and actual OBU hardware. Repeat efficiency measurements on your own target.

Measured outputs, checkpoints, configuration and audit are retained under `examples/real_pilot/`. Treat them as preliminary observations and debugging evidence. Further development and an independently held-out final evaluation are needed for a convincing research result.

## Not verified

Windows execution was not available here; the Python package and commands are designed to be cross-platform, but were executed on Linux/Python 3.12. Actual OBU hardware, secure aggregation, live networking, all attack families, all traffic scenarios and real-map alignment have not been tested in this release. The optional road geometry adapter is covered by unit tests only.
